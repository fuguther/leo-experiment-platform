## 1. packet_bits（P0 blocker）

**事实**（实测）：
- config.py:281 默认 **8_000_000**（8 Mbit = 1 MB 聚合单元）；E0 冒烟 trace 实际就是 8 Mbit
- E0 工程基线 profile（280x14）与 acceptance 族为 **1_000_000**（任务书讨论的 1 Mbit）
- 量纲差：1 Mbit 相对 1500 B 包放大 **83.33×**；8 Mbit 放大 **666.7×**

**裁定（可回滚）**：**双口径并存**，两个都不撤销：

| 口径 | 值 | 用途 | 约束 |
|---|---|---|---|
| aggregate-8Mbit | 8,000,000 | 与平台默认一致，保留历史可比性 | 结论必须标注为 aggregate packet，不得当作典型 IP 包 |
| aggregate-1Mbit | 1,000,000 | 与任务书讨论口径一致，E0 工程基线用值 | 同上 |
| packet-real（代理） | 由真实包长分布决定（当前仅有二手锚点 1471.64 / 891 / 372 / 64 / 1500 B） | 量纲对照与敏感性分析 | **不得**声称是真实 Starlink 包长分布 |

**复算工具**：r5_packetization_check.py（给定 packet_bits、速率与候选包长，算决策请求率与放大倍数，并做双向单位一致性自检）。

**要收敛需要**：owner 指明正式 profile 用哪个值，以及是否接受用 CAIDA/MAWI 公开分布做 packet-real 代理。在此之前**任何包粒度结论都必须带口径标签**。

## 2. Starlink 链路标称口径

**事实**：三处并存——100 Gbps（任务书 §R3 + 证据台账 L1）、200 Gbps（对话正文与《直接数据提取与适用边界.md》）、6×400 Gbps（V3 设计）。

**裁定（可回滚）**：
- linkgen_published_optical_100g.yaml 取 **100 Gbps**，理由是它出自**任务书自身**（§R3/R7 明确要求"运商 100 Gbps optical"分 profile）；
- 200 Gbps 与 6×400 Gbps 作为**候选替代口径**记录在文件头注释与本表，**不撤销、不合并**；
- 引用该 profile 的结论必须写"厂商标称 100 Gbps 容量诊断"，**不得**表述为实测链路能力（厂商标称 ≠ 任意时间/方向满速）。

**要收敛**：owner 指定 published 口径的正式数值。

## 4. δ_min（最低实质效果量）

**事实**：任务书 §2 要求"依据先导实验数据尺度，不得用测试集定"。可用先导尺度（E2-F 实测）：ISL 候选链路 p95 排队延迟 0.160–0.600 s；ΔT_arrival（p50，8 臂恒定）0.017669 s；每包 F2 处理时延 0.15 / 0.45 s。

**裁定（可回滚，暂定）**：按预注册 §5 的**选项 (c)** 执行——由 E3 开发集实测 paired difference 的尺度确定，并在确认性运行前冻结。开发集结果出来前，先用**选项 (a)** 的量级作哨兵值：**δ_min = 0.05 s**（≈ p95 排队延迟下沿量级）。

**标注要求**：凡引用 δ_min 的结论必须写明"暂定值，待开发集尺度确定后冻结"。
