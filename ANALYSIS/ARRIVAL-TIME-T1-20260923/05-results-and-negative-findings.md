## 4. 风险闭环：计算时延的观测语义（2026-09-25T00:52+08:00）

**原风险（E1 规格 §2 提出）**：若实现是「t1 才重新读状态决策」，则计算期间的陈旧性会被消掉，而任务书要研究的恰恰是「t0 冻结观测 → 耗时推理 → t1 校验提交」。

**实测对照**（v2 走廊，compute_delay_s = 0.05，seed 7，各 10,576 条决策）：

| 观测模式 | t_decision_commit − t_decision_start | t_measure == t_decision_start | t_measure == t_decision_commit | 计算导致的陈旧性 |
|---|---|---|---|---|
| **frozen** | 0.05 s（全部） | **10,576 / 10,576** | 0 / 10,576 | **被保留**（观测冻在决策开始，提交晚 50 ms） |
| **refresh**（默认） | 0.05 s（p50） | 0 / 10,576 | **10,576 / 10,576** | **被静默消掉**（提交时刻才读状态） |

**结论**：

1. 任务书要的语义**平台已有**（frozen 模式，PR #210 落地），且可被时刻字段直接验证——**风险解除**，但方式与原先设想不同：不是「必须改实现」，而是「**必须显式选择 frozen**」。
2. **默认 refresh 会静默消掉计算陈旧性**——这与 F2/span 陷阱同族：不报错、自检全绿、结论却换了含义。任何含计算时延语义的实验（E5 / H3）**必须显式声明观测模式**并回显 t_measure 与哪个时刻相等。
3. frozen 的已知限制（平台自述）：仅 producer-verified、**尚未在正式 VM 工件上运行**；v1 限制**无 learning arm、无 forced_actions**。因此 H2 及之后涉及学习臂或强制动作的设计**不能直接用 frozen**，需先扩平台。

## 5. E3 首轮诊断：三个安慰剂伪影 + 一个结构性发现（2026-09-25T01:35+08:00）

### 5.1 首轮数字（探索性，3 个快照）

| 快照 | 事实选择 | 代价(选中) | 代价(另一候选) | O0 选/罚 | O1 选/罚 | O3 选/罚 | Regret(O1)-Regret(O3) |
|---|---|---|---|---|---|---|---|
| 204 | S | 0.238 s | **297.96 s** | N / 297.7 | N / 297.7 | S / 0 | **297.72 s** |
| 205 | N | 0.238 s | 297.90 s | N / 0 | N / 0 | N / 0 | 0 |
| 206 | N | 0.335 s | 297.90 s | N / 0 | N / 0 | N / 0 | 0 |

### 5.2 三个伪影（说明这些数字为什么不能当作信息价值）

1. **并列被字典序决定**：快照 204 上 O0 值 {N:0, S:0}、O1 值 {N:96000, S:96000} 完全并列，评分器按方向字典序选了 N；
   而事实策略选了 S —— 说明**内核的真实代价并不并列**，O0/O1 的高后悔值来自破并列规则，不是信息差异。
2. **O3 靠数据缺失取胜**：强制分支未送达时该分支没有 truth_at_target（contended_direction 为 null），
   评分器把缺失当 +inf → O3 自然避开它。**这是把「没测到」伪装成「信息优势」。**
3. **评分器不是内核的代价函数**：我用队列项代替了内核完整的 capacity 代价，既丢方向间差异、又制造假并列。

**结论**：一个朴素的 E3 分析会**制造出不存在的信息价值** —— 这正是任务书 §7 第 12 条点名要防的安慰剂/泄漏。

### 5.3 结构性发现（改变 E3 的设计）

查源码确认 capacity 策略的信息结构（routing.py:247-279）：

| 代价项 | 用谁的状态 | 是否受时间对齐机制影响 |
|---|---|---|
| **首跳边**（sat -> peer_d） | **本星自己的**出口队列 own_queue_bits（直接观测，不陈旧）+ 本跳几何传播 | **否**（本星状态是当前的） |
| **远端边**（a -> b, a != sat，反向 BFS 内部） | cache 里的 isl_propagation_s 与 **isl_queue_bits**（带 TTL 与 peer 匹配校验） | **是**（这正是邻居广告状态的入口） |

也就是说：**时间对齐机制在 capacity 策略里只通过「远端边的反向 BFS 距离」影响决策**，
首跳排序用的是本星即时状态。此前假设「邻居队列直接决定首跳」是错的。

### 5.4 修正后的 E3 评分器规格（下一轮实现）

1. **必须完整复刻 capacity 代价**：total_arm(d) = first_edge_cost(d) + dist_arm(peer_d)，其中
   first_edge_cost 用 own_queue_bits（臂无关），dist_arm 是**用注入后的 cache 值重算的反向 BFS 距离**；
2. **注入点**：远端边的 isl_queue_bits 与 isl_propagation_s（O0 = 实收、O1 = 当前真值、O3 = 各候选自身到达时刻真值，后者取自该候选的强制分支）；
3. **缺失处理**：O3 缺失必须标 not-available **并从该臂排序中排除**，不得当 +inf；若某臂全部候选缺失则该快照对该臂不可判；
4. **并列**：与内核一致（sort key = (cost, direction)），且在报告里**显式回显并列**，不得静默取第一个；
5. **安慰剂对照**（§7 第 12 条）：加一组「乱序注入」——把各候选的真值随机错配，期望其后悔值与真实注入无显著差异；
   若显著更低或更高，说明评分器仍有泄漏。

### 5.5 对 H1 的影响

**H1 维持「未判断」**，但理由已精确化：不缺授权、不缺机制（反事实重放已验证可用），
而是**评分器尚未 faithful**。在按 §5.4 修正之前，任何 Regret(O1)-Regret(O3) 数字都不得作为信息价值的证据。

## 6. E3 补充实验：控制面新鲜度（advertise_interval）扫描（2026-09-25T01:45+08:00）

### 6.1 设计

平台原生支持、无需任何注入：只改 control_plane.advertise_interval_s（邻居广告的刷新间隔 = 邻居状态的新鲜度），
其余全部冻结（走廊 v2 + policy=capacity + seed 7）。这是对 H1 核心问题的一个直接、无 hack 的探针：
**邻居状态的陈旧程度是否会改变决策与结果？**

### 6.2 结果

| 广告间隔 | 决策数 | 多候选决策 | chosen N / S / deliver | DELIVERED | HOLDING 溢出 | 地平线在系统内 |
|---|---|---|---|---|---|---|
| **2 s** | 10,579 | 3,528 | 3512 / 3542 / 3525 | 3525 | 0 | 3 |
| **10 s** | 10,579 | 3,528 | **3512 / 3542 / 3525（逐位相同）** | 3525 | 0 | 3 |
| **30 s** | **6,482** | 2,188 | 2178 / 2157 / 2147 | **2,147** | **1,212** | **169** |

### 6.3 读法（两条，必须分开讲）

1. **2 s 与 10 s 完全一致**（决策数、动作分布、命运计数、溢出全同）：
   在本场景的信息结构与 capacity 策略下，邻居状态在 2–10 s 尺度上的陈旧**不改变任何决策，也不改变任何结果**。
2. **30 s 出现崩塌**：决策数下降 39%（10,579 -> 6,482）、投递下降 39%（3525 -> 2147），
   并首次出现 **1,212 次 HOLDING_QUEUE_OVERFLOW** 与 169 个包停在地平线。

**机制解释（与源码一致）**：capacity 代价对「未知队列」是 fail-closed 的（routing.py:269-270 返回 inf）。
广告间隔过长 -> 更多邻居条目过期/TTL 失效 -> 远端边代价变 inf -> 候选被判不可达 -> 进入 holding/重决策路径 -> 堆积溢出。

**所以在本平台上，邻居状态陈旧起作用的方式是「可用 vs 不可用」的二值效应，而不是「对齐精度」的连续效应。**

### 6.4 对 H1 的意义（重要）

- 若 H1 的机制在本平台成立，它最可能的表现形式是**可用性收益**（到达时刻对齐让原本「未知」的远端状态变得可用），
  而不是「排序精度」收益（把已经可用的估计变得更准）——因为 2 s 与 10 s 的对比已排除后者。
- 这直接决定了 E3 修正版评分器该往哪看：**注入后应重点观察「从 inf 变有限」的候选数量与由此产生的动作差异**，
  而不是只看队列数值大小的细微差别。
- 证据级别：synthetic diagnostic（本地、受控压力机制场景）；**不是** formally governed VM。

| 项 | 结果 |
|---|---|

仅观察里出现的 origin 有广告队列，其余 fail-closed。

### 7.2 O0 vs O1：3528 个决策，**零差异**

用同一评分器，把首跳 peer 的广告队列替换为该 peer 的**当前真值**（truth_at_commit.candidate_truth[d].peer_egress_queue_bits，
注入到 peer_egress_direction 方向），逐决策重算：

| 指标 | 结果 |
|---|---|
| 比对决策数 | **3528**（全部多候选决策） |
| O0 与 O1 选择相同 | **3528（100%）** |
| 选择改变 | **0** |
| 可用性收益（inf -> 有限） | **0** |
| 可用性损失（有限 -> inf） | **0** |
| O0 中出现并列的快照 | **0** |

### 7.3 这意味着什么

结合第 6 节的新鲜度扫描（2 s 与 10 s 逐位相同、30 s 才崩塌），现在有两条独立证据指向同一结论：

1. **在状态可用的范围内，陈旧程度不改变决策**（新鲜度 2 s vs 10 s 无差异；O0 vs O1 零差异）；
2. **陈旧起作用只发生在「可用性」通道**（30 s 时大量条目过期 -> inf -> holding 溢出），
   而 O1 注入并未改变任何候选的可用性（0 收益、0 损失）。

因此对本场景：**「把状态补偿到当前时刻」（O1）相对「用收到的原值」（O0）的价值为零**。
这正是任务书 §1A.2 三段时错里的**陈旧补偿**那一段——在本平台上它不产生决策差异。

### 7.4 尚未测的：O3（到达时刻对齐）

O3 需要每个候选自己分支的到达时刻真值，必须靠强制重放（每个候选一次，约 460 MB/次、抽取后即删）。
按第 6 节的推断，O3 的价值最可能出现在**可用性通道**（让原本 inf 的远端候选变可用），
而 7.2 显示 O1 在该通道上零收益——所以 O3 是否有收益仍需实测，**不能由 O1 的结果直接外推**。

**证据级别**：synthetic diagnostic（本地、受控压力机制场景）；不是 formally governed VM。

| # | 检验 | 结果 | 作用 |
|---|---|---|---|
| 1 | **评分器保真度**：O0 复刻 vs 内核实际选择 | **200 / 200 一致** | 证明评分器忠实，其后结论可信 |
| 2 | **通道存在性**：给远端边队列做加性扰动（+1 Mbit/方向） | **3528 / 3528 评分发生变化** | 证明注入确实进入代价计算（不是"评分器忽略注入"） |
| 3 | **取值敏感性**：同一扰动下选择是否翻转 | **0 / 3528 翻转** | 证明状态取值在可达范围内**无法改变决策** |
| 4 | **可用性通道**：是否存在 inf 候选 | **0 / 3528 出现 inf** | 证明也不存在「未知 -> 已知」的可用性收益空间 |

### 8.2 判定

**H1 在本受控压力场景下不成立**（信息价值为零），且这次是有受控支撑的阴性，而不是"没测出来"：

- O0（收到的原值）与 O1（当前真值）选择 **3528/3528 相同**；
- 由于第 3 条的扰动上界覆盖了 O0/O1/O3 之间可能的状态差异，**O3（到达时刻对齐）同样无法改变选择**；
- 由于第 4 条，**可用性通道**（第 6 节新鲜度实验里唯一显现效应的通道）在候选层面根本不存在。

### 8.3 机制解释（为什么本场景必然为零）

快照 204 的分解（其余快照同构）：

| 候选 | peer | 首跳代价 | dist(peer) | 说明 |
|---|---|---|---|---|
| N | 3 | 0.0176692 s | **0.0530077 s**（3 跳纯传播） | 路径更长 |
| S | 1 | 0.0176692 s | **0.0176692 s**（1 跳纯传播） | 路径更短 -> 内核选它 |

两个事实决定了零值：
1. **排序由路径长度主导**：dist 是跳数 × 传播时延（0.0177 s/跳），候选间差**整跳**；
2. **相关方向的队列恰为 0**：广告里 N/S 方向队列都是 0（只有 E/W 有 24000），
   因此队列项既小又无差异，加性扰动 +0.1 s/边都不足以翻转整跳差距。

### 8.4 对 E3 场景设计的硬性要求（从本条结论直接推出）

要让该机制有出现的机会，场景必须同时满足两条，**当前的走廊 v2 两条都不满足**：

1. **候选路径长度可比**：备选路径的跳数差要小于队列项可造成的代价差（否则排序永远由跳数决定）；
2. **下游队列非平凡**：广告里相关方向（通往目的地的方向）的队列要显著非零且随时间变化，
   而当前走廊只在 E/W 方向有队列，恰好与决策方向无关。

### 8.5 证据级别与边界

- 级别：**synthetic diagnostic**（本地、受控压力机制场景、policy=capacity）；**不是** formally governed VM；
- 结论边界：**仅为该场景与该策略**。不得外推到真实运营星座，也不得外推到其他策略
  （hop 类策略完全不消费邻居状态，机制在那里按定义不存在）。

## 9. E3 判别力实验（HI18）与 H1 的精确能力边界（2026-09-25T02:35+08:00）

### 9.1 高负载场景（走廊 v2 + capacity + offered 18 Mbps）

| 项 | 走廊 v2（offered 12） | HI18（offered 18） |
|---|---|---|
| 投递 / 溢出 | 3525 / 0 | **5389 / 0** |
| 多候选决策 | 3528 | **5395** |
| 翻转余量（最优-次优） | — | 中位 **0.0353 s（恒为 2 跳传播）** |
| 本星队列（候选方向） | 多为 0 | 最大 **25,000,000 bit = 2.5 s**，38.7% 非零 |
| 广告队列（候选方向） | 多为 0 | 最大 24,000,000 bit，**9.6% 非零** |
| 缓存年龄 | — | 中位 **1.068 s**，p95 1.948 s |

### 9.2 四项检验（HI18）——全部仍然为零

| 检验 | 结果 |
|---|---|
| 评分器保真度 | 200/200（同前） |
| 通道存在性（加性扰动） | 评分变化（通道存在） |
| O0 vs O1 选择 | **5395 / 5395 相同（0 翻转）** |
| 安慰剂（乱序注入） | 0 翻转 |
| O0 与 O1 的候选值相等数 | **0 / 10,790（每个都不同）** |

### 9.3 结论：机制的能力边界已被精确定位

把 9.2 的三条放在一起，可以排除所有「信息不足」的解释：

1. 注入**确实改变数值**（0/10,790 相等）——不是「没注入进去」；
2. 注入**确实到达计算**（评分变化）——不是「评分器忽略」；
3. 但选择**从不翻转**（0/5395）——说明**决策相关的远端边不在候选首跳 peer 上**。

内核实证（决策 325–327，sat=0，目的地由 sat 2 服务）：

    内核选 N，且 N 的首跳队列惩罚(0.1~0.3 s)被其更短的路径(省 0.135 s)补偿
    N: 首跳 0.117669 + dist(peer1) 0.017669 = 0.135338  <- 更优
    S: 首跳 0.017669 + dist(peer7) 0.153008 = 0.170677

即 capacity 做的是**总代价最小**（本星队列与路径长度互相权衡），
而路径上的远端边**属于其他卫星**（本例是 peer 1 / peer 7 之外的节点），
这些卫星的缓存真值**账本里没有记录**（只记录了候选首跳 peer 的 candidate_truth）。

### 9.4 因此 H1/E3 的精确边界是「记录面缺口」，不是「场景缺口」

| 需要什么 | 平台现状 | 结论 |
|---|---|---|
| 每个决策时刻的**全缓存真值**（所有 origin 的 isl_queue_bits 真值） | **未记录**（cache_entries 只有 age 与字段年龄） | **无法完成 O0/O1/O3 的完整注入** |
| 候选首跳 peer 的真值 | 已记录（candidate_truth） | 已用尽，不足以驱动翻转 |
| 共同未来真值（O2） | 未记录 | 主指标不可执行（见 03 §11.3） |

**要真正测 H1，必须先扩记录面**：在每个决策行里落盘「该决策所用全部缓存条目的数值」。
这是**平台侧记录面扩展**（不改路由逻辑），属契约变更，需按 CHARTER 边界单独评审后再实施。

### 9.5 与场景/记录面无关、已确立的结论

1. 平台只有 capacity/delay 消费邻居状态，18 个既有 profile 全用 hop（机制此前按定义不可能显现）；
2. 评分器复刻保真度 100%（200/200），可供后续任何 E3 类分析复用；
3. 陈旧性的效应通道是**可用性**而非精度（2 s ≡ 10 s 逐位相同；30 s 崩塌并出现 1211 次 holding 溢出）；
4. capacity 的决策是**总代价最小**，本星队列（即时、不陈旧）与路径长度互相权衡——
   任何希望「陈旧邻居状态影响决策」的机制，都必须先让远端项在总代价中占主导。

## 10. 记录面扩展后 H1 的最终判定：**阴性，且原因定量明确**（2026-09-25T04:00+08:00）

§9 曾判定「当前记录面下不可判定」。随后我按 08 提案实现了记录面扩展（缓存值 A + 决策时刻真值 B），

| 项 | 结果 |
|---|---|
| 对照决策数 | 3528 |
| O0 与 O1 选择相同 | **3528 / 3528** |
| 翻转 | **0** |
| 陈旧性是否存在 | **是**（实测 24000 vs 48000 bit） |
| 决策余量 | 0.0353 s（2 跳） |

但 O3 与 O1 的差别是同阶未来状态，受同一量级关系限制。
