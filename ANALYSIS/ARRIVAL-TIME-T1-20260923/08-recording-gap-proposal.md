# 08 · 记录面扩展提案：让 E3 的 O0/O1/O3 注入成为可能（待评审）

**时间**：2026-09-25 02:45+08:00
**性质**：**契约/记录面变更提案**，不是研究结论；按 CHARTER「契约进、实例不进」与「不为以后可能有用预留能力」的边界，本提案必须由 owner 评审后才可实施。
**起因**：E3 判别力实验（05 §9）已把「信息价值为零」的成因定位到**记录面缺口**，而非场景或评分器。

---

## 1. 缺口（精确）

要完成 O0/O1/O3 的完整注入，需要**每个决策时刻所用全部缓存条目的数值真值**。现状：

| 记录项 | 现状 | 后果 |
|---|---|---|
| 缓存条目的**字段年龄** | 已记录（truth_at_commit.cache_entries[*].payload_field_age_s，中位 9 个字段） | 只知"多旧"，不知"多堵" |
| 缓存条目的**字段数值** | **未记录** | 无法把远端边代价替换成 O1/O3 真值 |
| 候选首跳 peer 的真值 | 已记录（candidate_truth[*].peer_egress_queue_bits 等） | 已用尽，实测不足以驱动翻转（05 §9.3） |
| 共同未来真值 | 未记录 | 主指标 Regret(O2strong)-Regret(O3) 不可执行 |

**关键事实**：capacity 的决策是**总代价最小**，其中远端边代价来自缓存；而远端边属于**路径上的其他卫星**，它们的数值恰好是没被记录的那部分。

---

## 2. 提案：在决策行里落盘「本次决策所用缓存条目的数值」

在 **info_audit**（离线审计流）内新增一个字段，**不进入 observation_at_start**（保持在线可见性边界不变）：

    cache_values: {
      "<origin_sat_id>": {
        "isl_queue_bits":      {"N": {"peer": 3, "value": 24000}, "S": {...}, "E": {...}, "W": {...}},
        "isl_propagation_s":   {"N": {"peer": 3, "value": 0.01766}, ...}
      }, ...
    }

要点：
1. 只落**数值**与 peer 身份，不落推导过程；字段与现有 payload 结构一一对应（control.py:103,106 的 isl_queue_bits / isl_propagation_s）；
2. **仅离线**：与现有的 truth_at_commit / truth_at_target 同级，受同一套字段白名单与 fail-loud 测试保护（00e）；
3. 与现有 cache_entries（年龄）并存，不替换。

---

## 3. 体量（实测估算）

| 项 | 实测 |
|---|---|
| 每决策缓存条目数 | 中位 4、最大 4 |
| 每条目方向数 | 4 |
| 每条目字段数（现按年龄记录） | 9 |
| **新增字节/决策** | 约 **384 B**（4 条 × 4 方向 × 2 字段 × 12 B） |
| **1 万条决策合计** | 约 **3.66 MB** |

结论：**体量可忽略**（相对现有决策流 138 MB / 时间线 16 MB）。

---

## 4. 它会解锁什么

| 解锁项 | 说明 |
|---|---|
| **O1 完整注入** | 把远端边的 isl_queue_bits 换成"当前真值"，重算反向 BFS -> 真正的陈旧补偿对照 |
| **O3 完整注入** | 把远端边换成"各候选自身到达时刻真值"（需在各强制分支内折叠账本后取该字段） |
| **O2（共同未来）** | 若同时记录"固定/自适应未来时刻"的同结构真值，则主指标 Regret(O2strong)-Regret(O3) 可执行 |
| 安慰剂对照升级 | 乱序注入可在同一结构上做，泄漏检测更有力 |

---

## 5. 它**不**改变什么（边界声明）

1. **不改路由逻辑**：capacity/delay/hop 等策略的代码不动，只是把已经读到的缓存值多记一份；
2. **不改变在线可见性**：新增字段只进 info_audit，不进 observation_at_start，在线臂拿不到它；
3. **不改变既有结论**：E1 的七项校验、E2/E2-F 的场景结论与身份口径均不受影响；
4. **会改变 code_sha256**（内核记录面代码变动）-> 必须**重新执行** E1 保真度自证与 receipt 契约测试，并重新声明身份。

## 10. 补丁 v6：加入「真值记录」后，E3 对照已跑通（2026-09-25T04:00+08:00）

### 10.1 发现的缺口与补齐

v3 只记录**缓存值**（= O0），但 O1/O3 需要那些起源星的**真值** —— 单靠缓存值无法构造补偿对照。
补丁据此扩展为两组字段：

| 字段 | 内容 | 支撑哪一组 |
|---|---|---|
| payload_values.isl_queue_bits | 决策时刻缓存里**看到的**队列值（含 peer 身份） | **O0** |
| truth_queue_bits | 同一起源星在同一时刻的**真值**（data+ctrl 位，口径同 own_queue_bits） | **O1** |

真值来源：内核的 self.isls[origin]（按卫星号索引的列表），已在补丁中做健壮的键类型转换。

### 10.2 验收：5/5 全通过（在一次性快照内实测）

| # | 判据 | 结果 |
|---|---|---|
| 1 | 记录结构 | **3528 / 3528** 多候选决策全覆盖，无缺失 |
| 2 | 语义无漂移 | **10,579 行决策序列逐位相同** |
| 3 | 在线边界 | **116 个测试全通过**（whitelist/info/audit/ledger/decision 子集） |
| 4 | E1 保真度 | **200/200，rate 1.0** |
| 5 | 体量 | **1,893 B/决策**（+20 MB，决策流 +20%） |

**体量最终更正值**：v1 4,751 → v3 1,377 → **v6 1,893 B/决策**（v6 = v3 的缓存值 + 真值，是功能完整的版本）。
§3 的 384 B 估算低估约 5 倍，引用一律以实测为准。

### 10.3 用 v6 跑出的 E3 全缓存对照（这是本轮最重要的结果）

    对照规模：3528 个多候选决策（走廊 v2 + capacity）
    注入范围：**全部缓存起源**（不再只是首跳 peer）
    结果：O0 与 O1 的选择 **3528 / 3528 相同，翻转 0**

而陈旧性本身是**真实存在**的，实测样例：

    origin 0：缓存值 E=24000 bit（seen）   真值 E=48000 bit（truth）   <- 差 2 倍

### 10.4 为什么仍然零翻转（定量）

| 量 | 值 |
|---|---|
| 决策余量（最优-次优路径） | **0.0353 s**（恒为 2 跳传播） |
| 陈旧导致的队列差 | 约 24,000 bit = **0.0024 s**（@10 Mbps） |
| 倍数关系 | 队列差比决策余量**小约 15 倍** |

**结论**：陈旧补偿（O1）在本场景的**量级不足以改变任何决策**——不是记录面缺失，也不是评分器问题，
而是**队列项在总代价中的权重远小于路径长度项**。

### 10.5 仍然欠缺的扩展 C（供 O3 完整版）

| 扩展 | 内容 | 状态 |
|---|---|---|
| A | 缓存值（O0） | **已实现并验证** |
| B | 决策时刻真值（O1） | **已实现并验证** |
| C | 各候选**到达时刻**真值（O3） | **未实现**：需要在 t_eta 处对全部卫星做一次定时快照（设计已明确，实现未做） |

按 §10.4 的量级关系，O3 与 O1 的差别是同阶的未来状态，**其效应同样受 15 倍量级差限制**；
但 O3 的**可用性通道**（inf -> 有限）需扩展 C 才能完全排除——这一点已如实标注。
