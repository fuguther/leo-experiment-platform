## 5. 更新：最廉价下一项实验 #2 已完成（2026-09-25T00:52+08:00）

## 6. 更新：H1 判定理由精确化（2026-09-25T01:35+08:00）

E3 首轮诊断已跑通机制（反事实重放 + 逐候选后果表 + regret），但**结论不可用**，原因已定位到评分器本身：

| 事实 | 证据 |
|---|---|
| 反事实机制可用 | branch_states_identical = true（3/3 快照的强制分支），action_changed = true |
| 但评分器不 faithful | 首轮出现三个伪影：破并列决定结果、缺失被当 +inf、代价函数未复刻内核 capacity |
| 结构性发现 | capacity 的首跳用本星即时队列；邻居广告状态**只经远端边的反向 BFS** 进入决策 |

**H1 判定：维持「未判断」**。理由：不是缺授权，也不是缺机制，而是**评分器尚未 faithful**；
在按 05-results-and-negative-findings.md §5.4 修正并加安慰剂对照之前，任何 Regret 数字都不能作为信息价值证据。

**最廉价下一项实验（更新）**：实现 §5.4 的注入式反向 BFS 评分器 + 乱序注入安慰剂对照，重跑 3 个快照。

### 7.3 决策：下一步做**具判别力的场景**，而不是直接停

按 05 §8.4 的两条硬性要求设计新场景（例如：让备选路径跳数相同或差 1 跳，并让通往目的地方向的下游队列显著非零）：

| 2 | 在新场景上重跑同一套四检验（保真度 / 通道 / 取值 / 可用性） | 不需要 |
| 3 | 若新场景下仍为零 -> 按停止条件停止复杂预测路线，保留阴性发现 | — |
| 4 | 若出现非零 -> 进入 E3 正式版（需要 O2 记录能力与授权） | 需要 |

### 7.4 本轮确定的、与场景无关的结论（可直接引用）

1. **平台只有 capacity/delay 消费邻居状态**；18 个既有 profile 全用 hop，机制在此前实验里按定义不可能显现；
2. **评分器复刻保真度 100%**（200/200），可用于后续任何 E3 类分析；

## 9. H1 最终判定（2026-09-25T04:00+08:00）

**判定：H1 在本场景不成立（阴性），原因定量明确。**

| 项 | 结果 |
|---|---|
| 对照规模 | 3528 个多候选决策（走廊 v2 + capacity，全缓存注入） |
| O0 vs O1 选择 | **3528 / 3528 相同，翻转 0** |
| 陈旧性 | **真实存在**（实测缓存 24000 vs 真值 48000 bit） |
| 决策余量 | 0.0353 s（2 跳传播） |
| 队列差量级 | ~0.0024 s |
| **倍数** | **队列差 ≈ 余量 / 15** |

**原因**：capacity 的总代价里，队列项权重比路径长度项小一个数量级以上，
因此无论怎样对齐邻居状态（O0/O1/O3），都不足以改变下一跳选择。

**这不是记录面问题**：记录面扩展（缓存值 A + 真值 B）已实现并 5/5 验收通过，对照已用完整信息重做。
