# RESULTS — 受控瓶颈机制实验：方向性错误是否被队列非线性放大？

> **边界声明（必读）**：本文件是**机制模型**（两条平行 corridor 的单服务队列），
> **不是 LEO 证据**，不含 140-sat kernel、不含 Starlink 数据。它只回答一个问题：
> 「当方向性错误负载 δ_r 逼近容量余量 ε_r 时，队列非线性是否会把它放大成延迟/队列损失？」
> 结论只能用于解释/约束 140-sat 的诊断，不能单独作为论文主张。

## 0. 结论（先说）

1. **放大确实存在**：τ=0（fresh 对照）在所有 20 个 (ε/μ, τ) 组合下逐包配对差 = +0.00 ms、
   flip=0、队列增长=0；一旦有观测延迟 τ>0，配对延迟差从 **+3.66 ms（ε/μ=0.50, τ=0.02）
   单调升到 +147.23 ms（ε/μ=0.02, τ=0.5）**，p95 最大 +271 ms、p99 最大 +316 ms。
2. **但"z>1 ⇒ 持续 queue growth"不成立**：窗口级队列斜率（stale）最大只有 **+0.043 pkt/s**，
   相对 fresh 对照的超额 ≤ **+0.011 pkt/s（≈1% 容量）**。放大是**有界振荡**（herding 换边），
   不是持续漂移。
3. **只有 transient（分箱）口径的 z 有判别力**：配对延迟差与
   **z_bin_p95 的相关系数为 +0.931**，与窗口级 **z_net 只有 +0.113**；
   与 flip 率 +0.454。窗口级 z_net 在整个网格里从未超过 **0.832**，却对应到 +147 ms 的损失。
4. **真正的放大通道是"接收超额那一侧的 1 s 局部队列增长"**：fresh 对照是 +0.01~0.14 pkt/s（噪声底），
   有 τ 时升到 **+15.3~16.4 pkt/s**（ε/μ≤0.05, τ=0.5），与该量相关性 **+0.963**（全网格最高）。
5. **对 140-sat 分析的直接含义**：窗口级 δ 与**"stale 运行实际负载 − fresh 运行实际负载"**
   不是同一个量。本模型里 |δ|（反事实口径）在 ε/μ=0.02 时是 1.35 pkt/s，
   而实际负载差只有 0.018 pkt/s（**差 75 倍**）。140-sat 的 z 用的是反事实口径，
   所以它可以在实际负载几乎没有变化时 ≥1 —— 这与"z≥1 但 backlog growth≈0"的观测**一致**，
   而不是矛盾。**建议**：在 140-sat 上补测 realized 口径（同 trace 的 τ=0 反事实运行的逐链负载差），
   见 §8。

## 1. 模型与口径

两条对称平行 corridor（0/1），各自独立单服务 FIFO 比特队列：

| 项 | 值 |
|---|---|
| 容量 μ | 100 pkt/s（一个服务时隙 = 10 ms），包长恒定 1 单位 |
| 背景负载 λ_bg | 每 corridor 相同到达表（外生、不可路由） |
| 可路由负载 λ_src | **固定 90 pkt/s**（整个 slack sweep 不变，避免 δ 与 ε 混淆） |
| 队列 | 主表：无限；敏感性：有限 50 包（drop-on-arrival，记录 overflow） |
| backlog(t) | queued + in-service 剩余（服务期内线性衰减）——与 `sq_persistence_analyze.py` 同口径 |
| 决策 | queue-aware greedy：`J_r = (observed_backlog_r + packet)/C`，相等时按 pid 奇偶交替（无方向偏置） |
| fresh | observed backlog = 到达时刻的真实 backlog |
| stale | observed backlog = (到达时刻 − τ) 的真实 backlog；τ ∈ {0, 0.02, 0.1, 0.5} s |
| flip | truth-substituted：committed vs **同一运行**真实 backlog 的 argmin（与 140-sat 分析器同口径） |
| δ_r | 每个 flip 记 (+chosen, −truth)/窗口，pkt/s；`Σ_r δ_r = 0` |
| ε_r | `μ − served_r/窗口`（反事实以外、实际剩余容量，≥0） |
| z_net | 窗口级 `\|δ_r\|/ε_r` |
| z_bin | **1 s 分箱**的 `\|δ_r,bin\|/ε_r,bin`；报 p50/p95/max 与 z>1 的 bin 占比 |
| 队列增长 | ①窗口级最小二乘斜率；②**超额接收侧（δ 较大的那条 corridor）的 1 s 局部增长均值**（放大通道） |
| 配对 | 同 seed、同 arrival 表（源与背景）、同 pid：`delay_stale − delay_fresh` |
| 种子 | 7/8/9，聚合为均值与 min/max（表内为 3 seed 均值） |
| 窗口 | warm-up 60 s + 测量 120 s（全部 20 cell 相同） |

确定性：arrival 表由 `random.Random("bottleneck|seed|rate|t_end").expovariate(rate)` 生成
（生成器与 arrival digest 记在每个 cell 的 `params` 里）；无 wall-clock、无未记录的随机。
`selftest` 断言 **τ=0 与 fresh 逐位相同**（flip=0、延迟分布相同）——这是内建负对照，不是假设。

## 4. 三个预注册预期的检验

| 预期 | 结果 | 证据 |
|---|---|---|
| z≪1 被吸收 | **部分成立**：接近容量但 slack 大时绝对损失小（+3.66~+15.53 ms），但**相对**比已达 1.30–2.29× |
| z~1 明显放大 | **成立**：z_bin_p95 从 1.02（ε/μ=0.20, τ=0.02）到 25.9（ε/μ=0.05, τ=0.5），配对延迟 +3.98 → **+146.37 ms**；p95/p99 同步恶化（+213.8 / +264.1 ms） |
| z>1 ⇒ 持续 queue growth | **不成立**：窗口级 stale 增长 ≤ +0.043 pkt/s、超额 ≤ +0.011 pkt/s；放大表现为有界振荡 |

**为什么第三条不成立**：herding 会换边。超额侧在 1 s 内可以涨到 +15 pkt/s，
但一旦 stale 快照显示它更拥堵，决策整体转向另一条 corridor，前者开始排空。
所以"每条 corridor 的 120 s 窗口斜率"正负相消 ≈0，而**局部**增长与延迟损失都很大。
把这一条写进结论时必须同时给"局部增长"和"窗口斜率"，否则会自相矛盾。

## 5. 判别力：谁能预测放大？

对 20 个 (ε/μ, τ) cell 求与配对延迟差的 Pearson 相关（跨 cell）：

| 统计量 | 相关 | 读法 |
|---|---|---|
| **bin growth excess-side** | **+0.963** | 最好的预测器，也是机制本身 |
| **z_bin p95** | **+0.931** | 分箱口径的 z 有效 |
| bins z>1 (excess) 占比 | +0.756 | 有效但受饱和 bin（ε_bin=0 → z=∞）影响 |
| flip rate | +0.454 | 弱；flip 率与损失脱钩（再证动作层≠性能层） |
| window growth（斜率） | +0.333 | 弱，因为正负相消 |
| **z_net（窗口级 \|δ\|/ε）** | **+0.113** | **几乎没有预测力** |

⇒ **z 的定义方式决定结论**。用窗口级 δ（`Σδ` 的净额）会把对称振荡误判成"无偏差"；
必须用分箱口径（或直接看局部增长）。

## 6. 机制（可复算的因果链）

1. stale 快照落后 τ；而队列在 τ 内已经变化 ⇒ 决策把整批包送向"τ 之前更空"的一侧；
2. 因为决策是**二选一且整源 90 pkt/s 全部重定向**，这一侧的实际 ρ 会越过 1
   （ε/μ≤0.10 时，超额侧 1 s 局部增长 +9.7~+16.4 pkt/s）；
3. 队列在 τ 量级的时间内积累，延迟按 1/(ρ−1) 放大（ρ 越接近 1，放大越陡）；
4. 当 stale 快照终于反映拥堵，决策换边，另一侧开始积累；
5. 结果：**延迟显著恶化、队列局部剧烈增长、但窗口净漂移≈0**。

数值锚点（ε/μ=0.05, τ=0.5，无限队列，3 seed 均值）：fresh 均值 72.50 ms
（p50 55.8 / p95 195.0 / p99 254.9），
stale 均值 218.80 ms（p50 205.0 / p95 459.4 / p99 551.7），
配对差 +146.37 ms；89.5% 的包变慢、9.9% 变快
（其余相同），frozen flip 率 55.1%。

## 8. 与 140-sat 数据的关系（谨慎，只是解释不是证据）

| 观测（140-sat，Round-2 C） | 本模型对应 | 关系 |
|---|---|---|
| C regime 下 52.8% 的 flip 落在 z≥1 的 0.5 s bin | z_bin 口径 | 本模型显示该口径**确实**预测放大（r=+0.93） |
| 但 z≥1 片段的 backlog growth ≈0、relaxed@+2 s 76–88%、E2E 无恶化 | 窗口级增长≈0 但局部增长大 | 本模型同样"窗口净漂移≈0"，却仍有 +147 ms 配对损失——**所以"无漂移"不能反推"无放大"** |
| E2E 对 AoI 不敏感（AoI 16.6 ms 仍 22.8–26.1% flip） | 本模型 τ=0.02（2 个服务时隙）仍有 +3.7~+4.2 ms | 方向一致：极小的 τ 也留下可测正效应，但在 140-sat 的 E2E 尺度（300–400 ms）上会被掩盖 |

**本模型无法解释的部分（必须写清）**：为什么 140-sat 里 z≥1 却连尾部延迟都不动。
最可能的差别是 **δ 的口径**：本模型里反事实口径的 \|δ\| 比"stale 与 fresh 两次运行的实际负载差"
大 5–75 倍（ε/μ=0.50 时 0.958 vs 0.181 pkt/s；0.02 时 1.347 vs 0.018 pkt/s）。
140-sat 只有反事实口径。**可执行的下一步**：在同 trace 上跑一个 τ=0（fresh 状态）反事实运行，
用 `z_realized = |λ_stale − λ_fresh|/ε` 重新分箱——若 z_realized 远小于 z_counterfactual，
则"z≥1 但无放大"就被解释为口径问题，而不是机制不存在。本模型的 `\|delta\| realized` 列
就是该量的原型（表内最大仅 0.18 pkt/s）。

## 9. 限制

1. **不是 LEO**：两跳拓扑、单源单宿、单一背景流；无传播时延、无多 flow 竞争、无逐包路径。
2. λ_src 固定为 90 pkt/s 是为了让 δ 可比，代价是 ε/μ 与 λ_bg 强耦合（λ_bg 从 5 到 53）；
   若改成"固定 λ_bg 扫 λ_src"，δ 的绝对大小会随 cell 变化，z 的可比性下降。
3. 决策是**整源二选一**，herd 占比远高于 140-sat 的单包级决策；
   因此本模型的放大是**上界式**的机制演示，不能直接换算成 LEO 的 ms。
4. ε/μ=0.02 的参考本身接近临界（M/D/1 ρ=0.98 的弛豫时间 ~2500 时隙），
   窗口级增长在该档不可信（§7.1 已给多 warm-up 对照）；配对差不受影响。
5. z 在 ε_bin=0 的 bin 记 ∞；`bins z>1 (excess)` 因此会被饱和 bin 抬高（ε/μ≤0.05 时中位 z 已是 ∞）。
6. 有限队列只在 50 包一档做过；overflow 与延迟损失的分界未做网格。
7. 三个 seed；τ=0.02 的小效应量级接近 seed 噪声。
8. 只做了"queue-aware greedy"一种策略；hysteresis/EWMA 在本模型中未实现。
