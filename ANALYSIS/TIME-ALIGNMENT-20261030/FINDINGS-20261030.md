候选数分布：1 个 = 2 111，2 个 = 802，3 个 = 1 743。

### C3 差分漂移 vs 决策 margin（成立，但受 margin 门控）

| 量 | p50 | p90 | p99 |
|---|---|---|---|
| 共模漂移 `mean_ρ(Q(T)−Q(t_g))` | 20.6 kbit | 923 kbit | 5.93 Mbit |
| **差分漂移** `|D_ab|`（top1 vs top2，t_g→T） | **0.47 ms** | 5.70 ms | 20.5 ms |

- **差分漂移是中位数 384 kbit ≈ 共模（20.6 kbit）的 19 倍** ⇒ 漂移不是共模，是候选特有的（C3 的必要条件）。
- 但 `|D|` 通常远小于 margin（p50 比 0.04）；**跨过 margin 的比例约 8.3%**（有符号 `D > M`，n=2 543）。
- **`Λ > 1` 不等于反转**：在 Λ∈[1,2) 与 ≥2 两档里 P(反转) 只有 58.8% / 58.0%（因为负号的 `D` 不构成跨越）。
  有符号判据 `D > M` 与真实反转的一致率 **99.4%** —— 该用时**带符号的差分漂移 vs margin**，不是 |Λ|。

### 为什么反转只有 8.9%：分数结构上的实测边界

对 2 548 个"≥2 个已评分候选"的决策，测每个分数项在候选之间的跨度（max−min）：

| 分数项 | 跨度 p50 | p90 | 均值 |
|---|---|---|---|
| `remaining_prop_s`（路径长度先验） | **16.70 ms** | 44.35 ms | 23.67 ms |
| `resource_work_s`（队列状态，唯一随状态时刻变的项） | **0.337 ms** | 7.75 ms | 2.04 ms |
| `local_egress_wait_s`（本地出口队列） | 0.503 ms | 10.29 ms | 3.05 ms |
| `prop_s` / `peer_process_s` / `resource_packet_tx_s` | 0.42 / 0 / 0 ms | 4.26 / 0 / 0 | 1.51 / 0 / 0 |

**只有 2.4% 的决策里队列跨度大于传播跨度**（62/2 548）。
即：在冻结的 router（`queue_weight=1.0`，未调参）下，决策 margin 主要由**路径长度先验**决定，
候选状态只是近并列时的裁决项。这不是"时间错位不重要"，而是"它的作用域被策略的代价结构限定了"——
正是 C3/C4 反转集中在最小 margin 四分位（27.7%）的直接原因。

**方法学含义**：任何"把 temporal effect 调出来"的 queue_weight 调整都会同时改变研究问题；
本报告的结论一律以原始参数（queue weight 1.0）为准，并把"policy-dependent"写成结论的一部分。

### 使用时刻语义的稳健性（T_arrival vs T_service）

同一个 `T_ρ` 争议（见 TIME-STATE-SEMANTICS.md §3）在本数据上是**可量化**的：

| 语义 | 反转数 | 反转率 |
|---|---|---|
| `S2 = Q(T_arrival)`（本文采用，FIFO 工作量的因果相关量） | 227 | **8.9%** |
| `S2' = Q(T_service)`，`T_service = T_arrival + Q(T_arrival)/rate`（candidate 臂现行口径） | 214 | 8.4% |

两种语义选出的动作在 **98.4%**（2 505/2 545）的决策上相同，只在 40 个决策上分歧。
⇒ "用哪个使用时刻"会把反转率移动 **0.5 pp**，不改变任何结论方向。
这条同时是对 `f666b59` 语义不一致的定量界定：它值得在论文里声明，但不足以推翻 C3/C4。

### 普遍性（供 C6 用，不能当严重性）

| 口径 | 值 |
|---|---|
| 反转动占**全部采样决策** | 227 / 5 000 = **4.54%** |
| 反转动占**多候选决策** | 227 / 2 545 = 8.9% |

## 4b. C5：same-continuation 反事实 fork（3 个决策，EXPLORATORY）

对 C4 已确认的反转决策，用 `CODE/scripts/counterfactual_one_decision.py` 做严格配对 fork：
同一 config / trace / seed / arm=now，先跑到同一 decision，再用 `kernel.forced_actions` 强制改变该决策的 action；
`counterfactual.branch_fingerprint` 证明两个分支的分叉点状态**完全相同**，其余 continuation policy 相同（common random numbers 由确定性仿真天然满足）。

选择规则（在看到 fork 结果之前定）：按"模型内局部代价"排序的反转决策，全部满足 `chosen == stale 动作`，
因此**一次强制运行 + 自带 baseline 就给出两个分支**。

| decision | 分支 A（stale 动作，= 原 run 基线） | 分支 B（到达时刻真值动作） | `R_d = e2e(A) − e2e(B)` |
|---|---|---|---|
| 18 589 | S，11 跳，**120.5 ms** | E，21 跳，172.4 ms | **−51.8 ms**（真值动作更差） |
| 43 570 | E，21 跳，**180.6 ms** | S，11 跳，90.9 ms | **+89.7 ms**（真值动作更好） |
| 96 253 | N，**36 跳，298.1 ms** | E，8 跳，63.4 ms | **+234.6 ms**（真值动作好得多） |

- 三次 fork 的 `branch_states_identical = true`、`action_changed = true`、`legal_at_branch_point = true`；
  `baseline_action` 与我们从 ledger1 分析出的 `chosen` **逐一相符** ⇒ 反事实确实落在**被分析的那个分支点**上。
- **C5 成立**：单个决策的动作改变造成 **52–235 ms** 的 E2E 变化，与整条轨迹的 e2e p50（117 ms）同量级。
  "动作变了但后悔≈0"（Case E）在本数据的这批决策上**不成立**。
- **但方向不是单向的**：3 个里 1 个为负（真值动作更差）。原因在路径长度，不在队列：
  - 决策 18 589：真值发现 S 出口队列从 2.0 Mbit 涨到 18.5 Mbit，于是改走 E；但 E 的剩余路径实际是 21 跳，
    而评分器的 `remaining_prop_s` 只按"5 跳 × 单跳传播"定价（34.3 ms），把 14 跳的绕行低估成 12 ms。
  - 决策 96 253：陈旧状态让包选了 N，实际走了 **36 跳**、298 ms；真值改走 E 只 8 跳、63 ms。
  ⇒ **真正决定损失大小的是路由器的路径代价模型与"无绕行/无路径进度约束"，不是状态新鲜度本身。**
- **网络外部性（cohort）**：改一个决策，同 run 里成千上万个包的送达时刻随之改变
  （三次分别为 3 198 慢 / 2 915 快、1 247 慢 / 1 647 快、498 慢 / 560 快），最大 |Δ| ≈ 232–235 ms；
  另有 18 / 13 / 3 个包的**命运**改变（DELIVERED ↔ ISL_QUEUE_OVERFLOW / IN_SYSTEM）。
  即：逐跳决策不是局部事件，单点扰动会在全网队列上重新分配。
- 覆盖限制：这 3 个决策都在**同一条干线**上（sat 4 / sat 124 一线，hop 5–6），不是全网的独立抽样；
  第 4 个 fork（`cf2-20261030-d89662`）被 OOM 杀死（exit −9，receipt 保留、run-id 不复用），所以 n=3。

### 与模型内局部代价的对比

三个决策的**模型内**局部代价分别为 15.3 / 15.6 / 26.4 ms，而**实际** |R_d| = 51.8 / 89.7 / 234.6 ms。
即评分器把这次动作改变的真实后果低估了 **3.4–8.9 倍**：它看不见"绕行 10–28 跳"这件事。

## 5. 场景性质（决定结论适用域，不能外推）

同 run 的 `congestion_metrics`：364 条 ISL 中 242 条有流量，
利用率 p50 **0.145** / p90 0.692 / p99 0.796 / max **0.798**；util≥0.2 的链路占 **29.9%**，≥0.5 占 13.7%，≥0.9 **0%**。
交付率 99.91%，D=0.15 s 时 miss 34.8 pp，e2e p50 117 ms / p95 236 ms；
全网 ISL 平均负载仅 7.1%（23.16 / 327.6 Gbit·s）⇒ **点拥塞、面空闲**（tokyo↔singapore 双向 560/589 Mbps 压在同一条 5 跳干线上）。

判定：这是**中载、排队可见但不饱和**（transition / queue-visible）区，不是传播主导区，也不是 ISL 溢出区。
因此本轮结论只能写成"在该 regime 下 C1–C4 成立"，**不得**写成普遍严重性。

**场景身份（由 `AUDIT-SCENARIO.md` 逐条核过，必须随每个数字一起引用）**：
- 业务 = **6 城合成 gravity（P(j|i) ∝ 1/d²）非齐次泊松**，9000 × 600 kbit / 0.9 s 发射窗；
  **不是** M-Lab、**不是**人口栅格、**没有** burst 变换、**没有** diurnal。
- 它落在 SPEC §3 表的"对比层（Kepler 140 星）"格子里，**不是** SPEC §2E 预注册的机制场景
  （后者是 24 星/3 面、8000 bit、ISL 5.5 Mbps、18 城、M-Lab OD、4 s）。
- 1.2 s 内几何只走 0.075°、0 次切换、0 次重匹配（静态拓扑）⇒ 本场景**只能**测"队列状态年龄"，
  测不到"陈旧几何/陈旧拓扑"。任何"拓扑陈旧"的表述在本场景不成立。
- 热点 ρ=0.798 **未进入** SPEC §2D 的 0.85–0.95 带；OD top-5 40.3% **刚压线** 40–70%。
  ⇒ 不得声称"已满足 SPEC §2D 全部结构判据"。
- `stage_c_e2_6g_adv200.yaml:1-10` 的文件头注释是**陈旧错误**（写着 24 星/10 Mbps/8000 bit），
  与本文件正文和代码冲突；引用参数只得以正文与代码为准。

## 7. 当前结论边界（必须原样引用）

1. **C1 成立**：年龄中位 103 ms。
2. **C2 成立**：绝对漂移中位 0.13 包，尾部到 26 包。
3. **C3 成立但有门控**：差分漂移非平凡（0.64 包中位），且是候选特有而非共模；但通常 ≪ margin，跨越率 8.3%。
4. **C4 成立**：该 regime 下 8.9% 的多候选决策会因"用到达时刻真值"而换动作；有符号判据 99.4% 一致。
5. **C5 成立（n=3，exploratory）**：3 个 same-continuation fork 给出 R_d = −51.8 / +89.7 / +234.6 ms，
   与 e2e p50 同量级；Case E（动作变了但后悔≈0）**在这批决策上不成立**。
   但**方向不单向**：1/3 为负；主导因素是路由器的路径代价模型低估绕行（3.4–8.9 倍）与"无绕行约束"，
   不是状态新鲜度本身。⇒ "用更新鲜的状态"不是解药。
6. **C6 未测**：只有 1 个 seed、1 个 regime、1 条轨迹；3 个 fork 全在同一条干线上，且第 4 个 fork 因 OOM 未完成。
7. 不得声称：真实 Starlink 流量/队列；LEO 典型参数（真实广告周期量级是 15 s，本场景 0.2 s，比现实"更新鲜"）；
   传播主导 regime 的结论；任何 E2E 显著性或"严重性"结论。
