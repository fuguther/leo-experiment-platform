# 状态年龄机制 pilot（2026-10-31）：设计与就绪证据

> 性质：DIAGNOSTIC / MECHANISM PILOT。不是 formal run，不进论文主表。
> 代码身份：本文件随 `night/time-exp-20261031` 的新提交一起冻结（提交 SHA 见
> `ANALYSIS/DEPLOYMENT-INDEX.jsonl` 的 run 记录与本文末的 trace hash）。
> 本文件只记录"怎么跑、为什么这样跑、起跑前证明了什么"，结果另见后续报告。

## 1. 这轮要回答的唯一链条

```
状态变旧 → 候选之间的相对代价变化 D → 是否超过原 routing margin M
→ 是否真的翻转 next-hop → 是否持续向同一资源偏流 → 是否形成 queue/congestion 放大 → E2E
```

只跑 140 星单一 regime 的 pilot，不重做 TAP 矩阵；低负载是负对照，高负载 + burst 是正对照。

## 3. 流量：30/70 background + hotspot + 单次 burst

不新写流量生成器；用现有 `scene_trace_program` 的 `s1_stationary` 声明式程序：

- OD 权重：`tokyo→singapore = 0.70`（热点单向 corridor）；其余 29 个有向对平分 0.30。
- 背景 30% 让"有替代 next-hop"成立，热点 70% 让目标 corridor 的定向 ISL 利用率
  可解析地落在 `0.7 × offered / 100 Mbps`：40/120/200 Mbps ⇒ 0.28 / 0.84 / 1.40。
  实际 rho 由 VM 实测决定，不预设。
- burst：新增可选 `pulse = {start_s: 8.0, duration_s: 0.5, multiplier: 1.6}`，
  全局乘子、只在高负载 cell 声明。它与现有 two-state 模型不同：**不保持长期均值**
  （明确是一个 treatment），目的是让状态变化时间尺度（0.5 s）短于广告周期（1 s）。
  生成器仍用同一套 Poisson thinning，majorant = base × peak × pulse，声明乘子精确。

## 4. 运行器与 contract

`CODE/experiment_platform/load_calibration.py`（contract + cell；本提交把它需要的
140 星 profile 加入 `ALLOWED_PROFILES`，并按跨臂 key `(pid, hop_index)` 补上
decision 投影里的 `hop_index`）。选择它的理由：
- 一个 cell 内一次 trace 编译、多 arm 顺序跑 ⇒ trace/seed/物理参数天然相同；
- 每 arm 写出 `decisions.jsonl.gz`（全量决策 + 完整 time_alignment 审计）、
  `result.json.gz`（packet_events / link_service_windows / congestion_metrics）、
  `target_probe.jsonl`（同 run 真值）；
- 输出有预算上限，不会产生 10 GB replay。

Contracts（新增）：
- `EXPERIMENTS/contracts/ta-pilot-calib-20261031.json`：cells `cal-040/cal-120/cal-200`，
  单 arm `now`，无 burst；`cal-120` 开 truth probe，用于起跑前的 probe 自检。
- `EXPERIMENTS/contracts/ta-pilot-arms-low-20261031.json`：cell `low-040`，arms
  `stale,now`，无 burst（负对照）。
- `EXPERIMENTS/contracts/ta-pilot-arms-high-20261031.json`：cell `high-120-burst16`，
  arms `stale,now,candidate`（若时间允许再补一个只含 `common` 的 cell，复用同一
  trace program ⇒ 同一 trace SHA）。

Contract 的 `deadline_s` 被 harness 冻结为 4.0 s；本 pilot 不把 deadline loss 当
primary endpoint（D=4 s 在本场景不 binding），只用它做 fate/loss 分解与 E2E 对照。

## 5. 起跑前就绪证据（本机，FACT）

1. **四臂语义**：在线路径 `kernel._score_order` 调用 `_ta.plan_decision(probe)`，
   无显式 target 覆盖；`arm_target_at` 是唯一 arm 依赖输入；候选集/资源映射/
   scorer/合法性/物理模型逐臂共用。`candidate_target_rule=arrival` 由本 profile
   设置，因此 candidate arm 的 `query_targets == eta_targets`。
2. **predictor**：`bounded_linear` = 同资源、已收到历史、相邻斜率排序取中位、
   锚最后样本外推、<2 样本退化 hold_last、无未来样本；`history_limit=4` 由本
   profile 显式设置（全仓默认 8，审计已确认）。
3. **candidate ETA**：8 项非重叠（compute wait/service、query wait/service、
   local egress wait、tx、prop、peer processing）；决策行同时记录
   `eta_terms / eta_targets / query_targets`，`t_measure/receive/decision` 可由
   `used_state` 与 audit 恢复。
4. **scorer**：8 类项齐全，另含 `resource_packet_tx_s` 与 `remaining_prop_s`
   （剩余跳数 × 单跳传播）；queue_weight=1.0。
5. **target probe**：commit 后登记；A/B 证明不改变业务结果；不消耗业务 RNG/资源；
   truth = queued(data+ctrl) + in-service remaining；`used_state` 行做
   identity+generation 校验。已知边界：downlink 目标的 fallback 行不可用作 truth
   （`identity_source != used_state`），分析必须过滤。
6. **修好的 red tests**：`test_target_probe.py` 两个测试桩缺
   `arrival_rate_bps`（产品类有该方法），本提交补桩；不是放松断言。
7. **定向测试**：`time_alignment / online / eta_terms / control / target_probe /
   scene_trace_program / load_calibration / prediction_accuracy / t1_tasks`
   合 198 passed。
8. **contract preflight**：5 个 cell 全部通过（profile 白名单、config 解析、
   trace_program 物化、输出目录检查）。
9. **本地端到端 smoke**（只作代码检查，不是科研证据）：
   12 s / 40 Mbps / candidate 单臂，`DIAGNOSTIC_COMPLETE`，natural_end=true，
   310 包 / 271,756 events / 28 s wall；5,913 条决策，3,605 条多候选，
   3,604 条 ≥2 完整候选；缺失信息只占 49/11,704 candidate slot（0.4%）；
   probe 11,704 行、11,392 条可用 ISL truth；`query==eta` 对合法候选成立；
   状态年龄 p50 0.53 s，ETA dispersion p50 4.25 ms，margin p50 12.6 ms，
   predictor 误差 median 0 / p90 10 ms（秒）。

## 6. 起跑前仍需满足的 gate（VM 实测后判定）

1. post-warmup time-alignment coverage ≥95%；2. 多候选决策 fallback ≤5%（只看合法候选）；
3. `target work == 0` 的候选比例不能 >80%；4. 最忙/目标 corridor 实测 rho ≥0.7；
5. access/compute/holding 非主瓶颈；6. NO_ROUTE / hop-cap 非主损失；
7. 多候选决策数量足够；8. probe 覆盖率足够；9. 四臂 trace hash 一致；
10. 除 arm 外 resolved config 逐字段一致。

任一 gate 失败：只修造成失败的那一个因素，重跑短 pilot，不跑矩阵。
