# 流量、带宽、时间维度：我们要盯住的东西

> 整理日期 2026-10-19 ｜ 场景：低轨星座分布式逐包路由 + 状态时间错位
> 基准实现：MA-DRL Routing Simulator（SatCom-TELMA），本机克隆在 /tmp/madrl，逐行读过
> 本机仿真器：leo-experiment-platform（CODE/leo_sim），配置与实测标定取自仓库内文档
> 本文只做分析与判据，不替代正式实验；凡"建议值"都标了可检验的判据

## 0. 摘要：五句话

1. **你现在的时间尺度是被流量参数"撑"出来的**：1 Mbit 的包 + 10 Mbps 的星间链路 = 每个包在链路上要占 **100 ms**，而一跳的传播时延只有 2–17 ms。参考项目里发送只占每跳总时延的 **0.3%–2%**，你这里是 **94%**。
2. **"要有 20%–40% 的排队"这句话有三种读法，互相冲突**。按排队论算，利用率 20%–40% 时平均队列只有 0.25–0.67 个包——等于没排队；要让队列本身占到 20%–40%，利用率得到 90% 以上。你说的多半是"20%–40% 的链路在排队"，那就得反过来：**少数链路打到 0.85–0.95，其余空着**。
3. **带宽受距离影响，但弱；时延受距离影响，且强**。你代码里的 DVB-S2X 模型：2.95 Gbps@400 km → 986 Mbps@2000 km → 284 Mbps@5000 km → 0@5827 km；传播固定 3.34 µs/km。真正需要按距离标定的是时延和可见性，不是带宽。
4. **"预测 50/60/70/80 ms" 这个跨度，在你当前的参数下小于一个包的发送时间**（100 ms）。也就是说，你已经预测到了"队列还来不及变化"的时刻——这不是预测器不行，是尺子量错了对象。
5. **先做"信息价值上界"，再挑五个预测器**。用完美未来状态选路，如果收益本来就小于运行间方差，换十个模型也救不回来。你之前四个时间臂一次偏好反转都没有，最可能就是这一条。

## 第一部分　流量与带宽：什么叫"合适的流量"

### 1.1 你的原话，我先翻译成可检验的说法

### 1.3 你改了什么，差在哪

`t1_pressure_corridor_v2.yaml`：`packet_bits: 1 000 000`（1 Mbit）+ `isl_rate_mbps: 10`（10 Mbps）。

| 量 | 参考项目 | 你现在 | 差 |
|---|---|---|---|
| 每包发送时间 τ_ser | 22–109 µs | **100 ms** | 1000× |
| 一跳传播 τ_prop（2000 km） | 6.7 ms | 6.7 ms | 不变 |
| τ_ser / τ_prop | ~1% | **1500%** | 传输变成主项 |
| 端到端时延 | 几十 ms | **0.46–1.04 s**（seed 7 实测） | 10–20× |
| 80 ms 内的包发送次数 | 700–3600 次 | **0.8 次** | 预测对象几乎不动 |

三个直接后果：

1. **"传输时间占比很低"这条已经被破坏**。你想要的物理性质，恰恰是目前配置里最先丢掉的。
2. **"预测 50–80 ms"落在一个包的服务时间之内**。10 Mbps 下每 100 ms 才有一次出队事件，50 ms 后队列要么没变、要么正好少一个包。四个预测跨度在物理上不可分辨。
3. **端到端 1 秒，而预测跨度 80 ms**，占比 8%。就算预测全对，对最后决策的影响也被 1 秒的排队淹掉。

### 1.4 带宽到底受不受距离影响

**分三层回答，别混在一起。**

1. **香农层**：接收功率 ∝ 1/d²，容量随距离单调下降，但对数尺度上很缓。你的模型把这段做成了 DVB-S2X 阶梯：0–440 km 满速 2.95 Gbps，之后每跨一个门限掉一档，到 5827 km 归零。
2. **体制层**：
   - **射频星间**（26/23 GHz，几百 MHz）：强距离相关，就是上表那种曲线；
   - **激光星间**（100–200 Gbps 口径）：**几乎不受距离影响**，受指向、云、可见性影响；距离只通过传播时延体现。
3. **时延层**：**严格线性**，3.34 µs/km，一跳 2–17 ms，端到端几十到上百 ms。这一层才是路由真正吃的距离。

**结论**：带宽"受距离影响但弱且阶梯化"，时延"受距离影响且是主项"。所以：
- 标定工作应该花在**时延 + 可见性 + 拓扑**上；
- 用一个常数 `isl_rate_mbps` 做压力场景是合法的，但必须写明"这是容量诊断，不是实测链路"；
- 一旦用 `rate_model: mcs`，链路速率会随几何周期性变化——这本身是**可预测的确定性成分**，别让神经网络去学它（见 §4.11）。

### 1.5 三个无量纲比值：判断"流量合不合适"的正确尺子

不要直接调"流量"，调这三个比值：

    R1 = τ_ser / τ_prop = (L_pkt / C) / (d / c)         每包发送 vs 每跳传播
    R2 = τ_queue / τ_prop = [ρ/(2(1-ρ))] · R1           排队 vs 传播（M/D/1 均值）
    R3 = Δ / τ_ser                                      预测跨度 vs 包服务时间

设计目标（建议）：

| 比值 | 目标 | 含义 | 现状 |
|---|---|---|---|
| R1 | ≤ 0.1 | 传播主导，发送可忽略 | **15** ❌ |
| R2 | 0.2 – 2（热点链路） | 排队和传播同量级，路径选择才有意义 | 与 R1 联动 |
| R3 | 5 – 20 | 预测跨度覆盖 5–20 个包的演化 | **0.5–0.8** ❌ |

这三条一旦成立，你想要的"传播为主、但队列有话说"就自动出现了；不成立，再怎么加预测器都是在噪声里找信号。

## 第二部分　"要有排队"：20%–40% 到底指什么

### 2.1 三种读法，差一个数量级

| 读法 | 定义 | ρ = 0.2 | ρ = 0.4 | 要让指标达到 20–40% 需要 |
|---|---|---|---|---|
| (a) 利用率 | λ/C | 20% | 40% | 就是 0.2–0.4 |
| (b) 有排队的链路占比 | 队列非空的链路 / 全部链路 | — | — | **热点链路 ρ 0.85+，其余空** |
| (c) 队列占用率 | 队列长度 / 缓冲上限 | 0.25 包 | 0.67 包 | ρ ≈ 0.9 以上，且缓冲不能太大 |

M/M/1 的均值：L = ρ/(1−ρ)。ρ=0.2 → 0.25 个包；ρ=0.4 → 0.67 个包；ρ=0.9 → 9 个包。
**所以 (a) 和 (c) 在 20–40% 这个区间里是互斥的**：利用率 40% 时队列几乎是空的。

你原话是"不能说每个链路都没有排队，它得有一些排队"——这句话说的是 **(b)**：
**20%–40% 的链路（或方向）处在排队状态**，而不是"每条链路都用掉 20%–40%"。

### 2.2 建议的判据（可写进 scene_check）

| 指标 | 建议阈值 | 为什么 |
|---|---|---|
| 全网有向链路平均利用率 | 0.05 – 0.15 | 真实网络不会处处拥堵；处处拥堵则路由无路可绕 |
| **有排队的链路占比（窗口内 p50 队列 ≥ 1 包）** | **0.20 – 0.40** | 你要的"有排队"，且留出可绕行的余地 |
| 热点链路利用率 p95 | 0.85 – 0.95 | 排队成为主项的唯一办法 |
| 丢包率 | < 1% | 否则 KPI 从时延退化成丢包 |
| 每跳排队/传播 | 0.2 – 2 | 队列对路径选择有实质影响 |
| 缓冲区 | 2–8 × BDP | 见 §4.6 |

### 2.3 你现在的场景离这个有多远

`T1-PRESSURE-WINDOW.md` 的实测标定线：`util_max ≈ 0.0235 × offered_mbps`（24 星 / 3 面 / 10 Mbps，seed 7）。

| offered | 12 | 20 | 40 | 80 |
|---|---|---|---|---|
| 最大链路利用率 | 0.291 | 0.495 | 0.565 | 0.557 |
| 交付速率 | 5.75 | 9.66 | 9.26 | 5.86 |

两件事：
1. **最大利用率 0.29 时，全网平均大概在 0.02–0.05**。也就是说现在是"一条热点 + 一大片空闲"，不是"20%–40% 的链路在排队"——虽然方向对，但分布形状不对。
2. **offered > 20 之后利用率不再涨**，因为接入先爆了。想继续往上压，只能改拓扑（收紧走廊 / 减卫星 / 缩 `max_isl_km`），不能加负载。

### 2.4 "输出功率很大"这句要改

在你的 DVB-S2X 模型里，10 W 在 2000 km 上的 SNR 已经高到 90 dB 量级，**把功率降到 0.1 W，MCS 档位基本不变**。真正封顶的是：

    速率上限 = 带宽 × 最高谱效 = 500 MHz × 5.9 bit/s/Hz ≈ 2.95 Gbps

所以"输出功率大 → 传输时间短"只在功率是瓶颈时成立；这里功率早就饱和了。要压缩 τ_ser，只有两条路：**加带宽，或减包长**。

顺带一句：这个链路预算没有干扰、没有雨衰、没有指向误差，2.95 Gbps 是"理想上限"，不能当实测写进论文。

## 第三部分　时间维度与预测器

### 3.1 四种时间处理，各自需要什么预测能力

| 臂 | 决策时用什么时刻的状态 | 需要预测的跨度 | 需要的能力 |
|---|---|---|---|
| **stale** | 收到的旧测量，原样用 | 0 | 无（但误差 = 陈旧度 × 变化率） |
| **now** | 外推到当前决策时刻 | 状态年龄（0.5–4 s） | 单步外推 |
| **common** | 外推到所有候选共用的未来时刻 | 年龄 + 共同前瞻 | 多步预测 |
| **candidate** | 各自外推到"若选它，包到达它"的时刻 | 年龄 + 每个候选自己的到达时刻 | **变长、多目标、逐候选** |

四臂不是四个模型，是**四个"用哪一时刻的状态"的定义**。这一点必须写清楚，否则评审会以为你在比四个算法。

### 3.2 先算"信息价值上界"，再谈模型

这是我最想让你加的一步，成本最低、否决力最强。

**实验 O（oracle）**：给路由器直接喂**完美未来状态**（仿真器里 t+Δ 的真值），跑同一批 seed，和 stale 对比。

- 如果 oracle 的收益 < 运行间方差 → **停止**。没有任何预测器能超过 oracle。
- 如果 oracle 有收益，再测"完美当前状态"（补到 now 的真值），差值就是"预测到到达时刻"这件事的**全部**价值空间。

**同时算两个数**（这两个数决定了 candidate 臂的天花板）：

    r   = 热点链路队列的变化速率（bit/s 或 包/s）
    Δt  = 两个候选的预计到达时刻之差（实测分布，不是假设）

则候选间可分辨的队列差 ≈ r · Δt。如果 r·Δt < 1 个包，candidate 和 common 在数值上就分不开——这与你之前"四个时间臂一次偏好反转都没有"的观察完全吻合，而且**这是设计问题，不是模型问题**。

我的估计：以你现在的参数（τ_ser=100 ms、广告周期 0.5–4 s、Δt 十几 ms），r·Δt 远小于一个包。**先把尺子换对，再谈预测器。**

### 3.3 预测目标必须唯一、可测、可对齐

定下来，别再改：

| 项 | 建议定义 | 备注 |
|---|---|---|
| 预测对象 | 有向链路队列占用 Q_d(i,t)，单位 bit | 不要和"剩余服务时间""可用带宽"混用 |
| 链路身份 | (卫星 ID, 方向 d)，**不要用链路实例 ID** | 拓扑每秒重算，链路 ID 会漂移，按 ID 建时序会得到垃圾 |
| 采样 | 控制面包到达时刻 + 决策时刻 | 事件驱动，不定时采样 |
| 预测跨度 | {50, 60, 70, 80} ms（若改参数见 §3.6） | 与 τ_ser 挂钩，不写死 |
| 真值 | 仿真器在 t+Δ 的真实队列 | 同一 run 内回读，不跨 run |

### 3.4 至少五个预测方法：选型 + 理由 + 成本

分三层，**每层至少一个**，否则五个模型会共错。

| # | 方法 | 家族 | 为什么放进来 | 训练成本 | 推理成本 |
|---|---|---|---|---|---|
| 0 | **持久化 / 线性外推** | 无 | 必备下界。任何模型打不过它就不该上线 | 0 | ~0 |
| 1 | **EWMA / Holt-Winters** | 指数平滑 | 传统基线，带趋势项，对阶跃负载反应快 | 0 | ~0 |
| 2 | **ARIMA / SARIMA** | 统计 | 文献标准对照；逐链路拟合，参数少 | 低 | 低 |
| 3 | **Kalman 滤波（局部线性趋势）** | 状态空间 | **最适合本题**：天然处理不规则采样和状态年龄 | 0 | 极低 |
| 4 | **XGBoost / LightGBM（滞后特征）** | 树 | 非线性、无需时序假设、对缺失鲁棒 | 低 | 低 |
| 5 | **LSTM / GRU** | 循环网络 | 时序学习的事实基线 | 中 | 中 |
| 6 | **TCN** | 卷积 | 并行、感受野可控，比 LSTM 稳 | 中 | 低 |
| 7 | **DLinear / NLinear** | 线性 | 2023 年证明"线性就能打平 Transformer"的强基线 | 极低 | 极低 |
| 8 | **Transformer（Informer / PatchTST）** | 注意力 | 长序列、多变量；论文里必须有 | 高 | 高 |
| 9 | **GCN-Transformer / ST-GNN** | 时空图 | 卫星网络的**空间相关性**是真实存在的，纯时序模型学不到 | 高 | 高 |
| 10 | **时序基础模型 zero-shot（Chronos / TimesFM）** | 预训练 | 不训练就能用，检验"是不是数据不够" | 0 | 中 |
| P | **排队论解析预测** Q(t+Δ)=max(0, Q+λΔ−μΔ) | 物理 | 用已知的到达率和服务率直接推，**可解释、可当 sanity check** | 0 | ~0 |

**建议的核心六件套**（对比实验够用，审稿也认）：
`持久化 → Kalman → ARIMA → XGBoost → LSTM → DLinear`，
再加两件加分项：`ST-GNN`（空间）、`zero-shot 基础模型`（数据量）。

**注意**：如果六个模型用的是同一套滞后特征，它们的误差会高度相关，对比就没有信息量。至少要保证**三种不同的归纳偏置**：无模型（持久化）、物理（排队论）、统计（Kalman/ARIMA）、树、序列网络、图网络。

### 3.5 怎么判断"预测得准不准"

分三层，缺一层就说不清"是模型不行还是仿真不行"。

**第一层：状态陈旧误差**（不训练任何模型）
用 t 时刻的测量直接当 t+Δ 的真值，算误差。这就是 stale 臂的误差，是**下界**。

**第二层：预测模型误差**（在完美当前状态上）
给模型 t 时刻的**真值**，让它预测 t+Δ。这隔离了"模型能力"，不受陈旧度污染。
指标：MAE、RMSE、MAPE（对 0 要特殊处理）、**方向准确率**（涨/跌判对没有）、分位数损失。

**第三层：闭环决策误差**
把预测接进路由，跑完整仿真。指标不是 MSE，而是：
- 换路率（预测改变选择的频率）
- 决策后悔值 = 所选路径实际时延 − oracle 最优路径时延
- 端到端 p50/p95 时延、丢包率

**误差分解公式**（写进论文很好用）：

    E_total = E_stale + E_model + E_sim
    E_stale : 用旧状态 vs 用当前真值
    E_model : 用预测 vs 用当前真值（在同样状态下）
    E_sim   : 仿真真值 vs 解析真值（用 Little 定律校验，见 §4.21）

如果 `E_model` 小但 `E_total` 大 → 不是模型问题，是陈旧度或仿真保真问题。

### 3.6 预测跨度必须和系统时间尺度自洽（最容易翻车的一条）

三个时间常数要摆在一张表里：

| 量 | 现在的值 | 应该是 |
|---|---|---|
| 包服务时间 τ_ser | 100 ms | 0.5–2 ms |
| 一跳传播 τ_prop | 6.7 ms | 6.7 ms |
| 状态年龄（广告周期） | 0.5–4 s | 0.1–0.5 s |
| 预测跨度 Δ | 50–80 ms | **≈ 年龄 + Δt，且 ≥ 5 τ_ser** |
| Δ / τ_ser | 0.5–0.8 ❌ | 5–20 |
| Δ / 年龄 | 0.02–0.16 ❌ | 0.5–2 |

两条硬约束：

1. **Δ ≥ 5 τ_ser**，否则队列在预测窗口里还没动。
2. **Δ 与状态年龄同量级**，否则"补到现在"这一步吃掉全部收益，candidate 臂的增量被噪声淹没。

按建议参数（τ_ser=0.65 ms，年龄 200 ms，Δt=20 ms），Δ 应该取 **0.2–0.5 s**，而不是 50–80 ms。
如果你一定要保留 50–80 ms，那就必须把广告周期压到 50 ms 量级并接受控制开销——这是另一个 trade-off，得单独测。

## 第四部分　你还没关注、但会决定成败的东西

### A. 流量结构（比带宽更能决定实验有没有信号）

**4.1 OD 空间集中度**
`uniform` 目的采样会让流量均匀铺满全网，结果是"处处同负载"，路由无路可绕、预测无处施展。
- 参考项目用人口图 + 每对网关均分；你现在有 `gravity` / `hotspot` / `mlab` 三种可选。
- **判据**：OD 矩阵的基尼系数或 top-5 流量占比。建议 top-5 OD 对承载 40%–70% 的流量。
- **为什么重要**：拥塞的空间局部性，是"绕行"这个动作存在的唯一理由。

**4.2 突发性 / 自相似**
泊松 + 固定包长的聚合流量非常平滑，队列几乎等于 λ/μ 的确定性结果——**所有预测器都会打平**。
- 文献里 LEO 业务普遍是二阶自相似（Demirci 系列），你现在的模型只有"阶跃 burst"这一种非平稳。
- **判据**：链路到达过程的 CV²（仓库 `BURST-DESIGN.md` 已经用 CV² 取代 Fano，方向对）。
- **建议**：至少加一档"重尾 ON/OFF"或"Pareto 到达间隔"，让队列有真实的涨落，预测才有东西可学。

**4.3 流的数量 / 聚合层级**
OD 对少 → 每条链路聚合的流少 → 到达过程方差大 → 队列抖；OD 对多 → 平滑。
这是"突发度"的另一个旋钮，且比 burst multiplier 更物理。

**4.4 负载的时变性**
**预测只有在非平稳时才有价值。** 恒定负载下，稳态可以由历史均值估计，stale 就够用。
- 建议至少三档：恒定、阶跃（+50%）、斜坡（30 s 内 +100%）。
- 你已有 `burst_start_s / burst_duration_s / burst_multiplier`，够用，但要保证 burst 发生在评估窗口内、且不在预热段。

**4.5 报文大小分布**
现在全是 1 Mbit（或 8 Mbit）。真实是双峰（小控制包 + 大块数据）。
固定包长会让服务时间确定化，队列演化变成纯到达过程——这对"可解析"是好事，对"预测有难度"是坏事。建议至少两档包长。

### B. 排队与缓冲区

**4.6 缓冲区大小（我怀疑这是被忽略得最厉害的一项）**
`isl_queue_bits: 256 000 000`（256 Mbit）。
- 在 10 Mbps 下 = **25.6 秒**的缓存；BDP（10 Mbps × 10 ms）只有 100 kbit，**缓冲是 BDP 的 2560 倍**。
- 后果：几乎不丢包，但排队时延可以到秒级——你实测 0.46–1.04 s 的端到端，主要就是它。
- 这也解释了为什么"队列占用率 20%–40%"不可能：20% 就是 51 个包 = 5 秒积压。
- **建议**：`isl_queue_bits` 取 2–8 × BDP。1 Gbps/6.7 ms 的 BDP 是 6.7 Mbit → 缓冲 16–64 Mbit；10 Mbps 的话 0.2–1 Mbit。
- 副作用要一起看：缓冲小了会开始丢包，KPI 从"时延"变成"时延+丢包"，得提前定好口径。

**4.7 KPI 到底看什么**
你之前的结论是"路径变了但交付率不变、时延变了"。那就必须明确：
- 主 KPI：p95 端到端时延（不是均值，均值会被大量短包稀释）
- 次 KPI：丢包率、未达标率（`deadline_s` 口径要与传播下界一致）
- **deadline 的设定**：至少 = 最短路径传播时延 × 1.5，否则所有包都"未达标"，指标失去区分度。

**4.8 队头阻塞与优先级**
控制面报文是 `nonpreemptive_priority`，会插队。控制流量占比很小（8000 bit/包），但它决定了"状态年龄"，而状态年龄是你整个故事的自变量。**控制开销必须单独计量**（`isl_ctrl.queue_area_bits_s`），不能混进数据队列。

### C. 链路与几何

**4.9 拓扑重算导致的"链路身份漂移"**
`recompute_interval_s: 1`，每秒重建图。同一条"链路"的邻居可能换星。
- 按链路 ID 建时序 → 训练集和测试集的"链路"根本不是同一条。
- **必须**用 (卫星, 方向) 做键，或干脆用相对几何特征（斜距、仰角、同面/异面）。

**4.10 几何是确定性的，别让模型去学**
斜距、可见性、同面/异面、太阳角，都是**可解析计算**的。把它们作为特征喂进去，比让 LSTM 从队列序列里反推要省 10 倍数据。
- 建议特征集：斜距、径向速度、剩余可见时间、队列、队列一阶差分、邻居数、本地面板占用。

**4.11 未建模的物理，要写成边界**
多普勒、指向误差、雨衰、星上热约束、激光云遮挡——你的模型里都没有。
- 不建模没关系，但论文里必须写"本仿真不含 X，因此结论不外推到 X"。
- 特别是激光星间：一旦声称 100 Gbps，就必须承认没有雨衰/云模型。

### D. 预测与决策的耦合

**4.12 误差代价不对称**
"以为空闲、其实堵了"的代价，远大于"以为堵、其实空闲"。
- 用**分位数预测**（预测 p80 队列）而不是均值，或用非对称损失。
- 这是预测文献里最容易被忽略、但对路由最实用的一条。

**4.13 闭环自激**
预测 → 改路由 → 改流量 → 预测失效。
- 所有候选都往同一条"看起来空"的链路绕，会在 Δ 之后把它堵死（herding）。
- **必须**做闭环评估，不能只报开环 MSE；并且要检查"预测引导的流量是否造成振荡"（换路率的自相关）。

**4.14 推理延迟预算**
星上算力有限。一个 100 ms 才能跑完的 Transformer，在 50 ms 的控制周期里毫无意义。
- 给每个候选模型记：参数量、单次推理时延（CPU 单核）、内存。
- **这是"五个模型对比"里最容易被审稿人问、又最容易答不上来的一项。**

**4.15 只在关键链路上准**
平均 MAE 会被 90% 的空闲链路稀释。要报**加权指标**：按"该链路上的流量占比"或"该链路是否进入过 top-10 队列"加权。
你关心的是热点链路准不准，不是全网平均准不准。

**4.16 预测器的多样性**
六个模型如果共享特征、共享训练集、共享损失，误差会相关，排序在不同 seed 间会翻。
建议：至少一个物理模型、一个线性模型、一个树模型、一个序列模型、一个图模型。

### E. 实验与证据（这些是你已经踩过的坑，别再踩）

**4.17 预热窗口污染**
`时间错位实验_预热窗口与四臂结论` 里的教训：旧曲线"更新周期越慢损失越大"，**几乎全部来自控制面尚未建立状态的那段时间**（预热段 11.17 倍，评估段 1.00 倍）。
- 必须固定共同预热 + 固定评估窗口，且用"实际历史覆盖"验证预热是否充分。

**4.18 效应量 vs 运行间方差**
四个时间臂在 6489 个决策里**一次偏好反转都没有**。先别急着换模型——先算：
- 配对差的置信区间（按 seed 做 paired bootstrap）
- 最小可检测效应（power analysis）
如果候选臂的理论增益本来就小于方差，实验设计再漂亮也测不出来。

**4.19 单种子 / 单场景外推**
`T1-PRESSURE-WINDOW.md` 自己写了"单种子，不得据此给统计结论"。这条纪律要保持。
- 至少 5 个 seed，报告 seed 为独立重复单位，不要合并计数当独立样本。

**4.20 配置漂移**
仓库里有真实案例：profile 写 600 s、支撑文档写 300 s；`available_capacity_interval_s` 不设时利用率恒读出 ~1.0。
- **每次实验前**用脚本比对 profile、resolved config、文档三处的关键字段（时长、速率、包长、队列、offered）。

**4.21 用 Little 定律做队列守恒校验**
对每条链路：L = λW（平均在队包数 = 到达率 × 平均排队时间）。
- 仿真器记录的队列面积、到达计数、排队时延三者应当闭合。
- 这是**唯一**能不依赖外部真值、检查"仿真器队列记账对不对"的办法。误差 > 5% 就说明有 bug。

**4.22 诊断 ≠ 正式**
仓库的证据分级（diagnostic / research_eligible）要守住。有回执、有差异，不等于可以写进论文。

### F. 还有三件可能被忽略的

**4.23 时间同步误差**
50–80 ms 的跨度下，星间时钟偏差 1–5 ms 就要命。仿真里时间戳是理想的，现实中不是。至少要在结论里声明。

**4.24 控制面开销与状态年龄的耦合**
广告周期调快 → 状态更新鲜，但控制流量挤占数据链路，且控制队列会排队。
- 这是一个**内生变量**：你测"状态年龄的影响"，就不能同时让控制开销自由变化。
- 建议：固定控制开销（绝对带宽），只变年龄，或在分析里把控制队列面积作为协变量。

**4.25 单位与量纲**
`queue_area_bits_s` 是"比特·秒"，不是流量。仓库里已经出现过一次误读。
所有指标表里带单位，别用"queue"这种含糊词。
