# 路线 A：把“堵”做出来（2026-10-19）

## 问题（实测，不是估计）

原三城探针场景（run `scpt-…-17`）的网络几乎是空的：

| 事实 | 值 |
|---|---:|
| 被预测到的有向链路 | 205 条 |
| 其中出现过积压 | **85 条**（120 条恒为 0） |
| 全网络最深一刻积压 | 226 291 bit = **19 个包，1 Gbps 上 1.8 ms 排空** |
| 链路利用率 | 87.5 Mbit ÷ 0.35 s ÷ 205 ≈ **0.12%** |
| 有积压的候选行占比 | **4.55%** |

根因：**96 星 × 4 方向 × 1 Gbps = 384 Gbps 总容量**，而全程只注入 87.5 Mbit。
设备参数（1 Gbps、1500 B、20 Mbit 缓冲）是对的，但这个组合把每跳序列化从旧场景的
60 ms 压到 **12 µs**，排队现象被物理地删掉了。这也解释了走廊场景里四臂决策 0/63 642 不同。

## 杠杆（先纠正一个我自己的错）

- ❌ **压缩发射窗不提高利用率**：ρ = 到达率 / 服务率，窗长只改变总比特与包数。
- ✅ **墙钟由包数决定，不由比特决定**（探针 7.2k 包 885 s；scds 32k 包 11 949 s）⇒ **加大每包比特几乎免费**。
- ✅ **集中 OD**：同样的流量压在更少的链路上，ρ 直接上去。

因此：保持设备参数不变，**把 12 000 bit 的包改成 120 000 bit，并把 6 个 OD 收到 2–6 个**，
让每个城市的出口速率固定在 0.8 Gbps（ρ≈0.8 于单条 1 Gbps ISL）。

## 验收判定

| 判据 | 目标 | h1 实测 | 结论 |
|---|---|---:|---|
| 候选间有真实差异的决策 | > 50% | **59.37%** | ✅ |
| 更好的状态信息能赢（选中非最空） | 高 | **50.11%**，均值 **2.28 Mbit** | ✅ |
| 接入等待不主导 | ≈0 | `access.wait_time_s_total = 0` | ✅ |
| 不被可达性混淆 | 无 NO_ROUTE | 4 631 全送达、0 NO_ROUTE、0 溢出 | ✅ |
| 候选行积压占比 30–50% | 30–50% | 23.39% | ⚠️ **未达标，原因已定位** |

**关于最后一行**：候选行里 **3/4 天然是冷方向**（四个方向只有 1 个在热路径上），
所以按行统计会被结构性地稀释——h2lo 在 ρ=0.4 时实测 13.1%，恰好≈0.4/4。
真正决定预测任务有没有意义的是**按决策**的两个数（59.37% 与 50.11%），它们都达标。
我先前把口径说成候选行 30–50% 是不准确的，此处更正。

## 结论与代价

- **采用 h1 作为路线 A 的场景**：2 个 OD（北京↔伦敦）、1600 Mbps、120 kbit 包、0.35 s 窗、
  1 Gbps ISL、20 Mbit 缓冲、每星 8 接入时隙。
- 它是**压力场景而非标定负载**：目的是让机制可观测，不能当作典型业务量陈述。
- 单格墙钟 350 s（VM），比原探针还便宜。
- 零预算预览：同一个 `hold_last` 在新场景里按预测排序与真值分歧 29.3%、分歧时多排 871 kbit；
  旧场景只有 11.9% / 13.6 kbit ⇒ **旧场景的赌注小约 65 倍，结构上不可能测出预测器改进**。
- 证据：`三端文件与同步治理/evidence/t1probe-20261019/hot-cal/`（每格的 probe 核验、
  run 身份、50 行原始样例、探针 sha256；`metrics.jsonl` 为汇总）。
## 四臂对照的意外结果：臂操作在 `hold_last` 下是空操作（2026-10-19）

batch `schot-20261019-20`：四臂（stale/now/common/candidate）各一格，同一热场景、同一 seed、
探针全开，4/4 rc=0，墙钟 360 s。结果：

| 项 | 结果 |
|---|---|
| 四臂预测 | 与 stale 相比，now/candidate **0/79 324 条不同**，common 仅 20 条（0.03%） |
| 四臂决策 | **0 / 26 069 条不同**（选了同一方向） |
| 业务结果 | 四臂完全相同：4 631 包全送达、0 NO_ROUTE、0 溢出、ISL 面积 6.34e6、接入等待 0 |

### 根因（代码事实）

`CODE/leo_sim/time_alignment.py`：

```
if method == "hold_last":
    value = last.queue_bits      # target_at 完全没被使用
```

而 `arm_target_at()` 的注释自己写着「This is the ONLY arm-dependent input」——
**臂唯一改变的输入正是目标时刻，而 hold_last 不读它。**
所以四臂在整个研究里一直是同一个预测器，这也解释了历史上「四臂决策 0/134 067 不同」。

### 这不是场景问题，场景这次是对的

同一场景里实测：

| 量 | 值 |
|---|---:|
| 有积压的候选行 | 23.39% |
| 候选真值有差异的决策 | 59.37% |
| 选中不是最空的决策 | **50.11%**，均值 **2.28 Mbit** |
| 信息年龄（snapshot − 源测量） | 中位 **38 ms**，p90 60 ms |
| 预测目标跨度 | 约 7 ms |

状态比预测跨度老 5–8 倍，且半数决策有 2.28 Mbit 的可省空间——**机制该起作用的条件都满足了**，
唯独预测器不消费目标时刻。

### 处置

新增契约 `scene_hot_arms_bl_20261019.json`：同场景、同四臂，`predictor` 改为 **`bounded_linear`**
（它会用 `target − last.measured_at` 外推，臂才真正不同）。四格 preflight 全过。
## 第二层瓶颈：观测通道（2026-10-19 深夜）

把 `predictor` 换成会读目标时刻的 `bounded_linear` 之后，stale 与 candidate **仍然 0/79 301 预测不同**。
探针记录了原因——**不是估计器的问题，是通道看不见**：

| 量（50 ms 通告） | 值 |
|---|---:|
| 预测资源的最新观测 > 0 | 9.32% |
| 真值 > 0 | 18.26% |
| **真值>0 但最新观测=0（漏看）** | **74.5%** |
| 信息年龄中位 | 40 ms |
| 预测目标跨度 | 约 7 ms |

通告每 50 ms 一次，而队列以 ~ms 尺度生成/排空 ⇒ **四分之三的真实积压从未进入任何样本**。
`hold_last` 与 `bounded_linear` 都被迫返回 ~0，四臂当然一样。

### 观测率校准（batch `schot-20261019-21`，2 格 rc=0，721 s）

同一热场景，仅把 `advertise_interval_s` 从 50 ms 改成 **5 ms**：

| 指标 | 50 ms | 5 ms |
|---|---:|---:|
| 漏看率（真值>0 而观测=0） | 74.5% | **38.7%** |
| 最新观测>0 的比例 | 9.32% | 12.99% |
| 预测非零比例 | 9.32% | 13.36% |
| 预测 \|误差\| 均值 | 442 181 bit | **196 879 bit** |
| **stale vs candidate 预测不同** | 0.00% | **6.53%** |
| **stale vs candidate 决策不同** | 0.00% | **0.00%** |
| 控制面 ISL 面积 | 1.22e4 | 1.22e4 |
| 业务结果 | 4 631 全送达 | 4 631 全送达 |

⇒ 观测通道确实是瓶颈（加密 10 倍后可见性与精度都翻倍），**但决策仍一条没变**。

### 最后一层瓶颈：队列深度相对评分尺度太小

预测差约 **0.2 ms**（200 kbit ÷ 1 Gbps），而评分总分约 **22 ms**（传播、跳数、本地排队主导），
占比 ~1%，**不足以改变候选排序**。

因此要让「状态新鲜度」真正改变路由，还差一步：**让队列深到与其它评分项可比**。
恒定速率 + ρ=0.8 的 M/D/1 平均队列只有 ~1.6 个包（192 kbit）；
要出现 10 Mbit 级队列，需要**突发源**（本项目已有 `s2_independent_burst` / `s3_correlated_hotspot`
两态包络模型），而不是继续抬恒定速率（会直接溢出）。

### 截至此处的净结论

1. 场景确实可以做出真实积压（已验证）；
2. 有了积压，**通道**是第二层瓶颈（已用 5 ms 校准验证）；
3. 通道修好后，**队列深度相对评分尺度**是第三层瓶颈（已定位，未修）。

三层都是实测定位，不是推断。三层都修好之前，任何「四臂无差异」的结论都**不能**
归因于状态时间机制本身无效——这一点此前从未被证明过。
